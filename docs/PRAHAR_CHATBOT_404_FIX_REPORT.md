## 1. Executive Summary & Problem Statement

When accessing the deployed Vercel web application and sending a query to Prahar Assistant, the user observed the following alert in the chat window:
```
Service Alert: ENDPOINT NOT FOUND (404)
Chatbot endpoint not found. Verify that VITE_API_URL is configured in your deployment settings and points to the live backend API ending in /api.
```

### The Definitive Finding:
1. **The React frontend is live and working on Vercel.**
2. **The Spring Boot backend has NOT been deployed to the internet.**
3. **Vercel is a static Jamstack/Edge hosting platform; it does NOT execute Java, Maven, or Spring Boot applications.**
4. Because the backend has not been deployed to a server/container host, the browser sent `POST /api/chat` directly to Vercel's static Edge CDN. Vercel's static file server looked for a static file named `/api/chat`, found none, and returned **HTTP 404 Not Found**.
5. To eliminate dead-end failures for evaluators while the backend is being deployed, **automatic graceful offline fallback** has been implemented in `chatApi.js`. When the backend is offline (404), Prahar automatically delivers verified safety guidance (with an `Offline Safety Guidance` badge).
6. To enable live Google Gemini 1.5 Flash AI responses, the Spring Boot backend must be deployed to a Java-compatible container host (such as Render or Railway) and its URL entered into Vercel's `VITE_API_URL`.

## 4. Root Cause Breakdown

| Cause # | Description | Trigger Condition | Service Returning 404 |
| :--- | :--- | :--- | :---: |
| **Root Cause 1 (Actual)** | **Backend not deployed to cloud.** Vercel only hosts the React SPA. Any call to `/api/chat` hits Vercel's static file server. | `VITE_API_URL` unset or defaulting to `/api` on Vercel | **Vercel Edge CDN** |
| **Root Cause 2 (Potential)** | **Subpath omission.** If the backend is deployed but `VITE_API_URL` is configured without `/api` (e.g. `https://api.com`), calls reach `/chat` instead of `/api/chat`. | `VITE_API_URL=https://api.com` without `getApiBaseUrl()` | **Spring Boot** |
| **Root Cause 3 (Routing)** | **Missing Vercel rewrite configuration.** Before `vercel.json` was added, Vercel had no SPA fallback rule. | User refreshes page on `/scanner` or `/assistant` | **Vercel Edge CDN** |

## 7. Step-by-Step Instructions: How to Deploy the Backend & Connect Vercel

Because Vercel cannot run Java Spring Boot, you must deploy the backend on a free/affordable Java container platform (such as **Render** or **Railway**).

### Step 1: Deploy Spring Boot on Render (Free)
1. Go to [dashboard.render.com](https://dashboard.render.com) and click **"New +"** $\rightarrow$ **"Web Service"**.
2. Connect your GitHub repository: `vibeshmourya/real-time-ai-ml-phishing-detection`.
3. Fill in the service settings:
   - **Name:** `prahar-backend`
   - **Root Directory:** `backend`
   - **Runtime:** `Docker` *(uses `backend/Dockerfile` already present in your repo)*
   - **Instance Type:** `Free`
4. Add these **Environment Variables** in Render:
   - `SPRING_PROFILES_ACTIVE` = `dev` *(uses in-memory H2 database; no external MySQL needed for quick setup)*
   - `SERVER_PORT` = `8080`
   - `AI_PROVIDER` = `gemini`
   - `AI_API_KEY` = *(Your Google Gemini API Key)*
   - `CORS_ALLOWED_ORIGINS` = `https://real-time-ai-ml-phishing-detection-88712kng8-vibeshmourya.vercel.app`
5. Click **"Deploy Web Service"**.
6. When deployment finishes, copy your Render service URL:
   `https://prahar-backend.onrender.com`

### Step 2: Configure Vercel with Your Backend URL
1. Go to [vercel.com](https://vercel.com) $\rightarrow$ open your `real-time-ai-ml-phishing-detection` project.
2. Navigate to **Settings** $\rightarrow$ **Environment Variables**.
3. Add a new variable:
   - **Key:** `VITE_API_URL`
   - **Value:** `https://prahar-backend.onrender.com` *(your actual Render URL from Step 1)*
4. Go to the **Deployments** tab $\rightarrow$ click the three dots (`...`) on your latest deployment $\rightarrow$ click **Redeploy**.
